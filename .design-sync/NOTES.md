# design-sync notes — @siplist/ui

Repo-specific gotchas for `/design-sync`. Append a bullet whenever the run learns something a future sync would otherwise re-discover.

## Source shape
- `@siplist/ui` is **source-only** — no `dist/`, no `exports['.']` (only subpath exports `./components/*`, `./hooks/*`, `./lib/*`). The converter runs in **synth-entry mode** (`[NO_DIST]` is expected, not an error): it bundles every `src/components/*.tsx` via a synthesized barrel. `.d.ts` contracts are extracted from the `.tsx` source via ts-morph.
- Components self-reference via the `@siplist/ui/*` alias (e.g. `import { cn } from "@siplist/ui/lib/utils"`). `cfg.tsconfig: "tsconfig.json"` wires esbuild's tsconfig-paths plugin so `@siplist/ui/*` → `./src/*` resolves during bundling. Do not remove it.

## node_modules target
- Run the converter with `--node-modules apps/frontend/node_modules`, **not** packages/ui's own. Reasons: (1) it carries the `@siplist/ui` workspace symlink → `packages/ui`, which is how PKG_DIR resolves in synth mode (no `--entry`); (2) it has both `react` AND `react-dom` (vendorReact needs react-dom; packages/ui only depends on react). Component deps (`@base-ui/react`, `cva`, `lucide-react`, `zod`, `sonner`, …) resolve via esbuild walk-up from `packages/ui/node_modules`.

## Styling (Tailwind v4, CSS-first)
- The DS ships **no compiled stylesheet** — it's styled with Tailwind v4 utilities inline in the component source, with tokens in `tooling/tailwind/theme.css` (`@siplist/tailwind-config`) and the **Source Sans 3** brand font (`@fontsource-variable/source-sans-3`).
- `cfg.cssEntry` points at a **freshly compiled** stylesheet produced by `.design-sync/build-css.sh` (wired as `cfg.buildCmd`). It scans `packages/ui/src/components/*` so every utility a component can emit is generated, inlines the `:root` tokens (light + `.dark`), and inlines 7 `@font-face` rules. The script also stages the woff2 files next to the css so the `url("./files/*.woff2")` references resolve and the converter copies them into `fonts/`.
- Output lives at `packages/ui/.cache/ds-sync/` (gitignored; inside packages/ui because `cfg.cssEntry` is bounded to the package dir). **Re-run `bash .design-sync/build-css.sh` before the converter on any re-sync** (the driver does not run buildCmd itself).
- The temp Tailwind entry is written transiently into `apps/frontend/.ds-styles.input.css` (so bare `@import`s resolve via the frontend's node_modules) and removed by the script. Also `@source`s `.design-sync/previews/*` so any Tailwind classes used in authored preview layout glue get compiled.

## Orientation attribute — resolved by shadcn/tailwind.css (2025-06)
- `@base-ui/react@1.5.0` emits `data-orientation="horizontal"|"vertical"`, and component source uses `data-horizontal:` / `data-vertical:` Tailwind variants. These compile to `[data-horizontal]` / `[data-vertical]` without the shadcn variant definitions — never matching.
- **Resolution:** `@import "shadcn/tailwind.css"` in `apps/frontend/src/styles.css` defines `@custom-variant data-horizontal { &:where([data-orientation="horizontal"]) }` and `data-vertical` equivalently. Adding this import to `build-css.sh` ensures the design-sync compiled CSS includes these variant definitions.
- This is the correct shadcn approach. A prior sync applied a source-level fix (replacing `data-horizontal:` with `data-[orientation=horizontal]:`) which was correctly reverted when shadcn components were updated. The CSS-level fix is more robust.
- **build-css.sh already has `@import "shadcn/tailwind.css"`.** Do not remove it.

## Preview authoring — base-ui component constraints
- **`DropdownMenuLabel` requires `DropdownMenuGroup` context.** `DropdownMenuLabel` wraps `Menu.GroupLabel` (base-ui), which throws `MenuGroupContext is missing` when rendered outside a `<Menu.Group>`. The error is async (React 18 concurrent) so the try/catch in the card harness doesn't surface it — the cell just renders blank. Always wrap label + its items in `<DropdownMenuGroup>`.
- **`DropdownMenuTrigger render={<CustomComponent>}` silently breaks.** The `render` prop on base-ui trigger works only with native HTML elements (`render={<button />}`) or components that properly forward `ref` and spread all HTML attributes. Custom `Button` components generally don't satisfy this at runtime in the headless capture env, causing blank renders. Use `DropdownMenuTrigger className="..."` directly instead.
- **Popover `defaultOpen` works; Menu `defaultOpen` also works** once the Group context fix above is applied. Both use base-ui portals that Playwright captures correctly within the configured viewport.

## Re-sync risks (watch-list for the next run)
- **Stale compiled CSS**: `cfg.cssEntry` is a build artifact regenerated by `build-css.sh`. If the Tailwind/theme/font versions in `apps/frontend` drift, the stylesheet changes. Always re-run buildCmd; don't trust a leftover `.cache/ds-sync/ds-styles.css`.
- **Tailwind CLI version**: `build-css.sh` pins `@tailwindcss/cli@4.2.4` (matches the catalog `tailwindcss`). If the repo bumps Tailwind, bump the pin in the script too, or the compiled utilities may diverge from what the app actually renders.
- **Font subset**: only the variable Source Sans 3 subsets referenced by the compiled `@font-face` ship. If a preview needs italic/other subsets, confirm they're in `fonts/`.

## Environment setup (learned 2026-10-19 re-sync)
- `pnpm` may not be on PATH. Install with `COREPACK_ENABLE_DOWNLOAD_PROMPT=0 corepack pnpm@10.19.0 i --frozen-lockfile` (the `sherif` postinstall then fails with `pnpm: command not found`, which is harmless). With no `node_modules`, `build-css.sh` dies on `Can't resolve 'tailwindcss'` and leaves `apps/frontend/.ds-styles.input.css` behind. Install first.
- The repo has no playwright. Install it into `.ds-sync/` (`npm i playwright@1.64.1`), which pins chromium-1248 and matches the cached `~/Library/Caches/ms-playwright/chromium-1248`.

## Conventions header corrections (2026-10-19)
- Fixed two errors in `conventions.md`. (1) `ThemeProvider` is not required for styling: tokens live on `:root`/`.dark` in the shipped CSS, and the provider only toggles `.light`/`.dark`/`.auto` on `<html>` (default `auto`). `ThemeToggle` calls `useTheme`, which throws outside the provider. (2) Source Sans 3 is declared `font-weight: 200 900`, not 300–900. Re-check both if `theme.tsx` or the font package changes.
